# 同野·游｜视觉风格纠偏与全站统一

这是对你正在开发的「同野·游」的视觉专项修改要求。请在当前项目上增量调整，不另建项目，不推翻已经完成的功能。

本轮目标：让用户端成为一个干净、精致、轻盈、适合现场使用的活动伴随工具。

它不是后台管理系统，不是产品营销页，也不是堆满二次元装饰的主题站。

本文件明确此前含糊的风格描述。业务、安全、分钟精度、数据保存和兼容要求保持不变。已有经用户确认的同野品牌规范优先于下文的备用配色。

## 一、先看真实页面，再修改

先检查当前项目的品牌文档、设计变量、公共组件和已实现页面，并运行当前版本。

记录活动列表、活动空间、计划、同行、我的和管理员编辑页的实际样貌。

找出具体的不一致，例如：
标题过大、卡片太多、圆角不统一、按钮抢眼、信息松散、功能藏太深、不同页面像不同产品。

不要不看页面就套一套新模板，也不要臆测截图中没有的信息。

沿用当前工作区，保护未提交修改。把检查与修改建议简短记入现有计划，随后落实，不要停在一份审美分析上。

本轮只改视觉、布局、组件呈现，以及为可用性所必需的局部交互。

不要顺手改数据库、权限、JSON 协议、同步语义、URL 契约、部署方式和业务算法。发现功能问题另行记录，不借换肤重写整个项目。

## 二、唯一视觉方向

关键词：克制、清楚、轻盈、连贯、耐看。

接近成熟原生工具的秩序感：
舒服的字级、明确的主次、自然的留白、一致的控件、及时但不过度的反馈。

借鉴这种原则，不复制任何品牌的专有界面。

“有质感”来自字体、对齐、比例和状态完整，不来自渐变、发光、大阴影或巨大圆角。

明确避开以下方向：

1. SaaS 后台
   统计卡片墙、KPI 数字、彩色图标方块、每个模块都是面板。

2. AI 模板营销页
   巨型口号、英文眉题、渐变标题、功能九宫格、无意义徽章。

3. 萌系或电竞主题
   糖果配色、粉紫渐变、荧光描边、星光粒子、表情图标堆砌。

4. 假苹果风
   巨大的空白、超大标题、满屏磨砂玻璃、胶囊岛和悬浮控件。

5. 牵强的户外风
   因为名字有“野”“游”，就添加山峰线稿、牛皮纸、做旧纹理、
   大面积土黄色和露营插画。

漫展的丰富感交给活动海报和内容，产品界面本身保持安静。

不要整站黑白到失去状态层次，也不要以“反模板”为由制造难用的新控件。

## 三、品牌与颜色

用户可见产品名统一为「同野·游」，归属「同野」。

沿用已有经确认的 Logo、字标和品牌用法。
不重新设计品牌，不擅自发明英文名称、吉祥物或宣传口号。
不要在每个页面都重复大号品牌名。

先查项目中已有品牌色和设计变量。
能直接复用就复用，不并行建立第二套主题。

没有明确品牌规范时，采用以下备用方案：

浅色模式：
- 页面底色：#F7F8F7
- 内容表面：#FFFFFF
- 主要文字：#202623
- 次要文字：#626B66
- 轻分隔线：#E3E8E4
- 品牌强调色：#2F6852
- 强调色悬停/按下：#265643
- 轻选中背景：#EDF3EF

这是一套中性白灰加少量沉稳绿色的工具界面，
不是把每个面板刷成绿色。

强调色主要用于：
当前导航、主要操作、选中项与关键路线。

不要让整页充满同等强度的彩色元素。

错误、警告、成功使用独立的语义颜色和文字/图标，
不把所有状态都涂绿。
主按钮和成功提示不能只有颜色差异。

正文、辅助文字、图标和选中状态均需实测对比度，
不能只凭肉眼觉得舒服。

深色模式单独定义表面层次，
不对浅色界面或地图整体反色。

深色模式备用基准：
- 页面：#121714
- 表面：#1C221E
- 主要文字：#E6ECE8
- 次要文字：#A8B2AA
- 分隔线：#333D36
- 强调色：#85B59A

深色强调按钮使用深色文字，
具体组合通过对比检查后再定稿。

活动海报中的颜色只属于海报，不自动改变整站主题。
禁止任意引入第二个品牌主色来装饰不同页面。

## 四、字体、间距与形状

中文使用系统无衬线字体，优先复用已有字体栈。

可用系统栈：
-apple-system、BlinkMacSystemFont、Segoe UI、
PingFang SC、Hiragino Sans GB、Microsoft YaHei、sans-serif。

不引入额外在线字体，不下载或打包付费字体。
不混用书法体、衬线体和装饰英文来制造“高级感”。

统一移动端字级基准：

- 页面标题：24–28px，600 字重。
  必要的活动名称可适度突出，但不做占半屏的 48px 标题。

- 区块标题：17–18px，600 字重。

- 正文与重要控件：15–16px，400/500 字重。
  手机表单输入优先 16px。

- 辅助信息：13–14px，仍应清楚可读。

关键日期、起止时间不降格成浅灰小字。
时间列表按列对齐，必要时使用等宽数字。

间距采用统一尺度：
4 / 8 / 12 / 16 / 24 / 32。

手机页边距通常 16px。
同类列表行、标题、按钮使用一致的对齐线，
不在每个页面各调一套。

圆角基准：
- 常用输入框和按钮：约 10–12px。
- 独立内容卡：约 14–16px。
- 底部 Sheet 顶部：约 20–24px。

已有成熟、接近此方向的组件可以保留，
不为了匹配一个像素全面重写。

胶囊形只用于确实需要的标签、筛选项或分段控件，
不把按钮、导航、列表和整张面板全部胶囊化。

普通内容主要靠留白和轻分隔线组织。
阴影用于真正悬浮的浮层。

不要给每个区域同时加边框、阴影、底色和多层内嵌卡片。

## 五、信息密度：不用卡片套卡片代替排版

活动是独立对象，适合用适量卡片展示。

摊位、场次、路线站点、成员和设置，
更适合清楚的行列表。

不要把一个日期、一项统计、一条提示、一组按钮
都包成单独卡片。

连续的信息放在一个自然区块内，
用对齐与间距建立关系。

同一交互区域只突出一个主要动作。

收藏、查看详情等高频辅助动作保留明确入口，
但不要与主操作使用同样的大面积实色。

只有必要的状态使用标签，不给每个词加边框。

重要操作不能为了极简藏进省略号菜单。
请在“清楚”和“少”之间优先保证清楚。

首屏要让用户知道：
我在哪个活动、现在看什么、下一步能做什么。

不要先看到一大块品牌宣传、数据统计或欢迎文案，
再向下找功能。

桌面端利用空间做合理分栏，
例如地图与地点列表并排，
不要只是把 390px 手机页面拉宽。

移动端不能横向溢出，
也不能同时叠三层导航和固定工具条。

## 六、每类页面应当是什么样

### 1. 活动选择

轻量品牌栏、清楚的搜索入口、必要的筛选、活动列表。

列表优先展示活动名、日期、地点和真实状态。
海报是辅助识别，不盖住关键文字。

活动少时不要预留一整排空筛选或分类卡。
没有海报时使用克制的文字布局，不生成假封面。

长标题应正常换行，
不能把用户识别活动所需的部分全部截断。

不做营销首屏，
不展示“管理 X 场活动、赋能 X 位用户”等后台数字。

### 2. 活动空间 / 逛展

顶部明确当前活动与日期。
切换活动可发现，但不抢眼。

继续沿用：
逛展 / 计划 / 同行 / 我的。

通用类型使用“活动”替代“逛展”。
本轮不另造导航架构。

地图与列表切换清楚。
查看地图时，地图本体占据主要空间。

搜索、过滤、回到全图等控件集中排列，
不让漂浮按钮散落四角。

地点详情使用统一的底部 Sheet：
名称和编号优先，
其次是位置、相关场次和操作。

缺失字段不留一堆空白占位。

### 3. 摊位与收藏

用紧凑、可扫读的列表展示：
名称、展位号和少量有用标签。

收藏图标位置统一。
已收藏和未收藏明显可辨，
不能只靠非常浅的颜色区分。

“收藏”“加入安排”“加入路线”视觉上能分辨，
但不强行做成三个同样抢眼的大按钮。

呈现与当前任务相关的主操作，
其他操作仍然可发现。

不要把收藏页做成电商商品瀑布流，
也不要为每个摊位生成彩色图标块。

### 4. 计划与时间

日期切换简洁。
时间、活动名、地点按稳定层次排列。

有时间轴，就让它真正服务于时间关系，
不重复展示另一套同样冗长的卡片列表。

必须保持分钟精度：
13:07–13:52 清楚显示、可以编辑。

不能因为视觉简化只剩“下午”，
不能把原始时间四舍五入。

快捷步长、数据精度与时间轴刻度继续分开。

我的安排、共同空闲、待提交修改、
冲突和需复核状态不能混在一起。

正常浏览保持清爽，
需要编辑时再展开相关字段，
不把所有编辑器常驻在日程旁。

### 5. 路线

有序站点和地图上的编号对应一致。

已走、下一站和未走有适量层次。
主路线清楚，辅助线退后。

选中点用大小、描边和颜色共同突出，
不让所有标点同时发光。

保留原始地图配色和图例。

没有已确认通道时，
不为视觉完整画一条看似可走的直线。

失效、缺失路段和估计时间保持真实。

### 6. 同行

像一个轻量同行工具，不像项目管理看板。

优先呈现：
当前小队、谁已确认、共同空闲结果和下一步操作。

成员状态用列表或紧凑行，
不为每个人造大型个人档案卡。

结果先给准确时间，
再按需要展开时间轴。

“已保存到本机”“已提交”
“尚未确认”“需要复核”必须可分辨。

不为了画面整洁统一改成“已完成”。

### 7. 我的与帮助

用清楚的分组设置列表组织：
身份恢复、导出、离线准备、主题和帮助。

不要给普通用户展示管理员统计、
部署模式、内部角色 ID 或技术日志。

帮助页采用适合阅读的正文宽度、标题、步骤和代码块。
不要把每一段教程做成卡片。

JSON 示例可以在自身区域横向滚动，
不能带着整页横向移动。

### 8. 管理员页面

可以更高密度，
但颜色、字体、按钮和反馈仍属于同一套产品。

采用明确的列表、表单分组、工具栏和编辑面板，
不做彩色仪表盘。

地图编辑的标点、连线、移动、删除模式必须明显，
不得为了隐藏工具栏导致误操作。

用户端不显示管理员编辑手柄。
管理员也能明确看到当前处于预览还是编辑。

## 七、控件、浮层与反馈

同一功能只使用一套组件规则：
按钮、输入框、日期选择、筛选、列表行、
空状态、Toast、Sheet 和对话框，
不能在不同页面各长一套。

优先改已有组件和少量语义化设计变量。
不为这次纠偏引入重量级组件库或独立设计系统工程。

不要大量内联写色值，
也不要叠加一层又一层覆盖 CSS。

具体要求：

- 按钮要有可辨识的普通、按下、加载、禁用状态。
  异步成功后才反馈成功。

- 移动端主要点击区域以至少 44×44px 为目标。
  不等于每个图标都画到 44px。

- 输入错误放在相关字段附近，
  不只闪一个转瞬即逝的 Toast。

- Sheet 的标题、关闭入口、滚动区和底部操作区统一。
  底部导航与系统安全区不挡内容。

- 不叠加多层 Sheet。
  使用当前项目合理的内部返回或状态切换，
  不改变深链接和返回语义。

- 页面加载保持稳定布局，
  骨架应对应真实内容，不满屏闪烁。

- 空状态通常只需要一句事实和一个合适的动作，
  不用巨大插画、励志话或营销文案。

## 八、文案要像工具，不像介绍工具的广告

中文为主，动作清楚，句子短。

统一使用已确认的：
活动、摊位、场次、计划、小队、共同空闲。

不要每页换一种叫法。

示例：

用：
“暂无收藏”
不用：
“开启你的探索之旅，收藏心仪摊位吧”

用：
“选择日期”
不用：
“请选择您心仪的活动参与日期”

用：
“3 人尚未确认”
不用：
“团队协作进度正在持续推进”

用：
“查看共同空闲”
不用：
“智能发现最佳同行时光”

用：
“地图尚未提供”
不用：
“精彩地图即将解锁”

用：
“已保存到本机”
不用：
在尚未同步时笼统显示“保存成功”

不要加入：
“极致体验、赋能、一站式、智能加持”等宣传词。

不要在 UI 中解释设计者为什么这样设计。
不要出现括号式自夸说明。

必要的安全、隐私、离线和错误提示不能删除。

简约是准确表达，不是假装没有限制。
详细背景放到帮助页，
不把每个控件写成说明书。

## 九、动效与现场使用

动效只服务于反馈和连续性。

普通状态变化约 120–180ms。
必要的浮层过渡约 180–240ms。
减少动态效果设置下关闭非必要移动。

不做弹簧乱跳、滚动入场、
背景漂浮、数字滚动和炫技转场。

不新增大面积模糊或持续动画拖慢地图。
不要自动飞地图、自动切 Tab，
或强制刷新打断用户操作。

现场默认可能是：
单手、强光、弱网、匆忙查看。

关键时间和按钮必须一眼能看清。

不能靠极细字体、低对比灰字和巨大留白，
换取截图上的“精致”。

## 十、实施顺序和验收

按以下顺序完成，
不要逐页各自自由发挥：

1. 检查真实页面，记录主要偏差。
   确定复用的品牌规范和唯一 token 来源。

2. 先统一颜色、字体、间距、
   按钮、列表行、输入与 Sheet。

3. 在以下页面验证这套规则：
   活动列表；
   带地图和详情的逛展页；
   带分钟时间与提交状态的计划页。

   把它们作为其余页面的基准，
   不要只验证一个漂亮的首页。

4. 统一同行、我的、帮助与管理员页面。
   保留已完成业务和全部必要状态。

5. 运行原有回归，
   补充关键视觉/交互检查，
   整理真实修改前后截图。

至少检查：
375px、390px、430px 移动视口与桌面视口。

覆盖：
浅色、深色、长活动名、多标签、无地图、
空收藏、加载、离线、失败、时间冲突和多人状态。

验收要能回答：

- 不看 Logo，各页是否像同一个产品？

- 不靠大卡片、渐变和阴影，
  信息层级是否仍然清楚？

- 进入页面能否快速找到
  当前活动、日期和主要动作？

- 收藏、安排、路线三种操作是否仍然清楚，
  没有新增数据副作用？

- 13:07–13:52 是否完整可读，
  输入、保存、导出与算法均未回退？

- 地图、详情 Sheet、底部导航、
  安全区和软键盘是否互相遮挡？

- 失败、未提交、待确认和需复核
  是否仍能被看见？

- 手机是否无需精细瞄准即可完成常用操作？
  桌面是否合理利用空间？

- 是否出现新增的英文装饰标签、无意义统计、
  假信息、巨型欢迎区或卡片套卡片？
  有就删除或改正。

将最终实际采用的规则记入项目已有设计文档。
没有则新增 docs/DESIGN.md。

只记录已采用的颜色、字级、间距、组件与页面规则，
不另造庞大流程。

业务文档仅在实际按钮名称变化时同步。

最终交付：
简要说明修正了哪些具体偏差，
列出改动文件、真实检查结果和同尺寸前后截图。

没有浏览器/设备条件的检查如实标为未验证。
不能用生成图片冒充实现截图。

生产发布继续遵守当前授权和发布流程，
不因为换肤擅自覆盖线上版本。

最后自查：

这是让人专心逛展、排时间、找朋友的工具。
让内容成为主角，让界面退后。
统一而不寡淡，简洁而不难用。
