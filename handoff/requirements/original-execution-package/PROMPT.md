## 2. 产品目标与明确不做的事情

### 2.1 一句话定位

**凑空：一个人发起，大家填时间，一起找到能碰面的空档。**

既支持不带场次表的约饭、自习、桌游，也支持带公共场次表的展会、校园活动和旅行安排。REDLAND 是模板和实际验收场景，不再是全站前提。

### 2.2 核心流程

发起人创建一次凑空 → 可选导入活动详情/场次 → 分享小队邀请 → 成员免注册填写自己的时间和安排 → 提交确认 → 大家查看共同空闲、选择部分成员比较 → 各自修改后结果更新。

不能再要求成员互相下载、发送、导入日程码才能更新在线小队。旧分享码只作为兼容入口和离线交换能力。

### 2.3 第一版不做

不做全站好友关系、聊天、支付报名、票务库存、自动抢预约、自动分组、AI 推荐、付费 API、复杂日历同步、邮箱短信账号体系、全站活动推荐和大型后台框架。CSV/ICS 导入导出、任意版式 OCR、强实时推送可后续做，不能挤占核心上线工作；没有完成的入口不要显示成可用。

“选择场次”只记录个人计划，**不代表替用户完成官方报名或预约**。

## 4. 领域模型与角色

### 4.1 活动模板 EventTemplate

保存可复用的背景资料：标题、说明、日期范围、时区、每日开放区间、活动与场次。管理员能发布公共模板；私人小队可以直接录入自己的活动，不必先创建全站模板。

模板更新生成内容版本，不原地覆盖所有使用它的小队。模板没有成员私密数据。

### 4.2 小队 Group

一次具体的多人协调空间，有标题、邀请权限、发起人、成员、状态和活动配置快照。

- 可以从模板创建，也可以只有标题、日期与每日候选时段。
- 两个小队即使使用同一 REDLAND 模板，也不能互相读写成员信息。
- 默认不被全站搜索、公开列表或搜索引擎索引。
- 活动配置绑定快照和版本，不能运行时始终读取模板“最新值”。
- 状态至少有 `open`、`closed`、`archived`；关闭回复与删除小队是不同操作。

### 4.3 成员 Participant

身份只在当前小队内成立，名字用于显示，不用于鉴权和唯一识别。同名可存在，通过稳定 ID 区分；改名不能产生新成员或覆盖别人。

创建者可以同时拥有一条普通成员记录，以便填写自己的时间；其管理权限与个人填写权限在代码中分开处理。

### 4.4 三类角色

- 平台管理员：维护公共模板、管理必要站点开关、处理滥用、停用小队、查看脱敏审计；不得在普通后台页面展示全体成员私密备注。
- 发起人：编辑本队活动、邀请、查看填写进度、管理本队成员、关闭/归档小队；不能冒充普通成员修改其时间，也不能看到未授权的私人备注。
- 普通成员：读取本队允许共享的信息，编辑自己的名字与时间，离开小队，导出自己的数据。

权限必须由 API 验证，不靠前端隐藏按钮。

## 5. 时间规范：用户明确要求细化，不能以小时为粒度

### 5.1 三层精度必须分开

| 层级 | 规范 |
| --- | --- |
| 存储、JSON、算法 | **精确到 1 分钟**，不存小时格子，不四舍五入 |
| 拖拽/快捷选择 | 默认 **15 分钟**；可选 **5 / 10 / 15 / 30 分钟**；不提供 60 分钟作为唯一/默认步长 |
| 手动输入 | 可以直接输入 `09:07`、`13:52`；输入组件 step 为 60 秒或有等效分钟级控件 |
| 时间轴 | 整点仅作主刻度；半点可作次刻度；根据缩放显示 5/15 分钟辅助线 |
| 最短共同空闲 | 默认 30 分钟；快捷选项 5 / 10 / 15 / 30 / 45 / 60 分钟；支持自定义 1–240 分钟并保留模板的合法默认值；按真实长度筛选 |

把刻度画细但仍按小时保存或计算，视为未完成。切换选择步长只能影响之后的新选择，**不能改动已有的 `13:07–13:52`**。

### 5.2 日期、时区与边界

1. 日期为真正有效的 `YYYY-MM-DD`，不使用 `10-03`、模糊本地格式或当前年份猜测。
2. 一个小队统一按活动时区显示，默认 `Asia/Shanghai`。第一版不强制按每个设备时区转换；页面与文档明确“活动时间”。不能让设备时区导致日期偏移。
3. 维护 `timezone` 字段并校验 IANA 时区。若暂未完整支持夏令时切换日，必须对该时区的过渡日明确拒绝并说明，不能默默按 1440 分钟推算跨 DST 的真实时长。上海场景不受此限制。该限制写入文档与测试，不宣传已经支持所有跨时区场景。
4. 日内时间用 `HH:mm`，开始只允许 `00:00–23:59`；结束额外允许 `24:00`，只表示该日期的结束边界。`24:00` 不能作开始。
5. 全部区间采用左闭右开 `[start, end)`。`10:00–10:30` 与 `10:30–11:00` 不冲突。
6. JSON 一个区间不跨日；跨午夜用前一日 `23:30–24:00` 和后一日 `00:00–00:30` 两段表示。日期必须都在活动范围内。禁止把 `23:30–00:30` 当成同日正向区间。
7. 每天可以有多个开放区间、多个可参与区间。午休和中途离开不是一个连续全天区间。
8. 缓冲先扩展忙碌区间，再合并，再裁剪到实际可参与范围；跨午夜的缓冲必须影响相邻日期，不能简单在当日 00:00 截掉。
9. 系统记录时间 `createdAt/updatedAt/submittedAt` 用服务端 UTC ISO 时间；活动日内时间是“日期＋时区＋分钟”，不要把二者混为一个不带时区的 JavaScript Date。

### 5.3 正确计算

对成员 i：

`个人可用 = (小队开放区间 ∩ 本人明确的可参与区间) − 合并后的个人忙碌区间（含本人缓冲）`

对明确选择的成员集合 S：

`共同空闲 = S 中各成员个人可用区间的交集`

再按真实分钟长度过滤最短时长。

- 普通活动默认缓冲 0 分钟；展会模板可默认 10 分钟；每个成员可以修改自己的缓冲，范围 0–120 的整数。
- 缓冲不作用于“我可以来”的边界，只作用于忙碌安排。
- 多段重叠忙碌区间可以保存并合并；同时参加的活动冲突给明确警告，不强行删除用户输入。
- 删除旧“每天超过 5 场”的全站规则。
- 没有任何已确认成员时不能返回“全天有空”。
- 未选成员不影响该子集的结果；选中但未确认/需复核的成员不能被偷偷忽略。
- 无全员结果时允许提示“仅查看已确认成员”或“放宽条件”，但必须由用户明确选择，不能伪装成全员结果。人数最多的备选推荐不是 P0 必须项。

### 5.4 必须通过的精确样例

在 `2026-10-03`、`Asia/Shanghai`：

- 小队开放 `09:00–12:00`。
- A 可参与 `09:00–12:00`，忙碌 `10:07–10:22`，缓冲 5 分钟。
- B 可参与 `09:15–11:50`，忙碌 `09:40–09:55`，缓冲 0 分钟。
- 未按最短时长过滤的共同空闲必须是：`09:15–09:40`、`09:55–10:02`、`10:27–11:50`。
- 最短 15 分钟时只保留第一、第三段；最短 5 分钟时三段均保留。
- 改变显示网格为 5、15 或 30 分钟，以上结果完全不变。

## 6. 成员填写、确认与同步状态

### 6.1 输入方式

无场次表时：直接添加本人可参与区间即可。有场次表时：先填可参与时间，再勾选已预约/已安排场次，或手动补充忙碌安排。两条路径使用相同的区间模型。

手动忙碌记录可包含标题、日期、起止、地点、来源、私密备注。公共结果只返回计算所需的可用/忙碌区间，不默认返回标题、地点或备注。

### 6.2 状态必须清楚

- `unsubmitted`：加入了，但没有确认过时间。
- 本地 `draft`：正在编辑或离线修改，尚未成功提交。
- `confirmed`：服务端已接受此版本，且对应当前小队时间配置。
- `needs_review`：已提交过，但引用的活动/开放时间发生了影响结果的变更，需要本人重新确认。

本地草稿和服务端已确认版本可以同时存在：用户开始改草稿，不应立即让所有人失去他上次确认的安排；页面应显示“有未提交修改”。服务端成功后才把新版本视为已确认。

`已保存到本机`、`已提交`、`待联网提交`、`需要重新确认` 不能混用。

### 6.3 特殊情况

- 已确认“全天可用”是明确操作，不是空数组自动推断。
- 已确认“这些天都不能参加”是有效回复；其可参与区间为空，但不是未填写。
- 选中成员中有人未确认，结果必须标明等待哪些成员。默认全员结果不得出现错误的全员可用。
- “8 人已加入，5 人已确认”与“这 5 人的共同空闲”分别显示。
- 小队加入人数只代表已加入者，不宣称未打开邀请的人已参与。
- 两台设备同一成员同时更新，用 revision 检查。失败返回 409，保留本地草稿，提供刷新比较/重新提交，不默默覆盖。

## 7. 页面与交互

### 7.1 首页

只突出“发起凑空”和“最近参加”，可进入公共活动模板与帮助。没有账号的最近列表只表示本机记录，清除本机后可用恢复链接找回云端资源，不能宣传全站账户历史。

### 7.2 创建

必填尽量少：标题、日期、每日范围。描述、地点、模板、场次、缓冲等渐进展开。普通约饭不应出现必填“展位/IP/参展日”。

创建成功后分开显示“邀请大家”和“我的管理入口”，管理凭据不能被默认复制到群聊。

### 7.3 小队内三页

- **安排**：本人日期切换、可参与区间、场次选择/搜索、手动安排、精确时间编辑、草稿与提交。
- **凑空**：默认全队，成员多选，真实结果卡片在前、时间轴在后，最短时长筛选、更新时间和未确认提示。
- **成员**：成员名、确认状态；发起人才看到管理入口。个人恢复/导出和离开小队有明确位置。

活动说明放小队顶部；个人主题和帮助不必占据主要 Tab。

### 7.4 时间选择的移动端要求

不能只支持鼠标拖拽。手机要能点击添加区间、精确编辑起止；拖拽时不能频繁误触整页滚动。分钟级不等于堆 1440 个格子；使用缩放/滚动时间轴或区间编辑器。短区间可以放大或通过列表准确选中。

浏览器返回、刷新、深链接、关闭弹层、从微信打开、PWA 冷启动都要有明确行为。离开未提交页面必须保护草稿。

### 7.5 审美与文案

中文为主，现代、克制、统一。浅色优先，支持深色和跟随系统。禁止紫蓝渐变堆砌、无意义大卡片、后台式指标墙和模板味营销页。

用户界面不写括号式自夸解释，不出现“为了提升用户体验”之类说明性碎嘴。必要的安全提示和状态提示不能省，详细说明放帮助页。颜色不作为唯一状态信号，支持键盘与减少动态效果。

## 8. JSON 导入与导出：必须可真正给普通人使用

### 8.1 导入入口

发起人和管理员都必须有可见入口，支持选 `.json` 文件和粘贴 JSON 文本。提供“下载最小模板”“下载完整示例”“格式说明”链接。不能只让用户改仓库文件或跑命令。

流程：读取 → 严格校验 → 预览（标题、日期、每天开放范围、场次数量、警告、更新差异）→ 明确确认 → 服务端再次校验 → 原子提交 → 回读核对。

JSON 只表示活动资料，**不得接受它授予管理员权限、成员身份、访问令牌或自动发布权限**。

### 8.2 唯一标准格式

文件根：

- `kind` 固定 `coukong.event`。
- `schemaVersion` 固定整数 `1`，这是结构版本，不是活动内容 revision。
- `event` 为活动详情。
- `meta` 可选，仅允许已定义的示例标记与来源说明，不影响权限。

活动：

| 字段 | 要求 |
| --- | --- |
| `id` | 必填，稳定外部标识，`^[a-z0-9][a-z0-9_-]{0,63}$`；不是服务器权限依据 |
| `title` | 必填，去首尾空格后 1–100 字符 |
| `description` | 可选，最多 5000 字符，纯文本 |
| `timezone` | 必填，有效 IANA 时区，默认使用 `Asia/Shanghai` |
| `startDate/endDate` | 必填，有效 ISO 日期；结束不早于开始；第一版范围最长 31 天 |
| `location` | 可选，最多 200 字符 |
| `defaultBufferMinutes` | 必填，整数 0–120 |
| `defaultMinSlotMinutes` | 必填，整数 1–240；通常为 30 |
| `defaultSelectionStepMinutes` | 必填，5、10、15、30 之一；通常为 15 |
| `days` | 必填，每个范围内日期恰好一条；包括关闭日（其开放区间为空） |
| `activities` | 必填数组，可以为空；不带场次的聚会用空数组 |

每日记录为 `{date, openIntervals:[{start,end}]}`。开放区间须按时间升序、不重叠；相邻区间可以规范化合并。关闭日用 `openIntervals: []`。

活动记录为 `{id,title,description?,location?,tags?,sessions}`。每条至少一个场次；标签最多 10 个、每项不超过 30 字符，不得重复或为空白。场次为 `{id,date,start,end,location?}`。

活动 ID 在包内唯一，**场次 ID 在整个包内唯一**。场次必须落在已声明的某个开放区间内；不同活动的场次允许互相重叠。不能因为有多个并行节目就拒绝整个活动包。

`meta` 允许：`isExample` 布尔值、`sourceNote` 最长 1000 字符的来源说明。时间、标题、场次不得凭空当成官方数据。

第一版上限：文件 UTF-8 字节数 512 KiB、31 天、最多 1000 个活动、**总场次数最多 1000**、每天最多 24 个开放区间。超过限制应拒绝并明确说明，不能截断或只导入前半部分。还要在 Worker 免费 CPU 配额内实测；如不能满足，应优化或明确缩小非核心上限并同步所有规范和测试，不得暗中改变 5 天 REDLAND 与分钟精度要求。

### 8.5 Schema、业务校验和版本

交付 `schemas/event-package.v1.schema.json`，采用 JSON Schema Draft 2020-12。若收到本提示词配套 Schema，直接纳入一致性检查；单独收到提示词也必须生成完整 Schema。

严格限制未知字段，说明没有注释、不允许尾逗号、编码 UTF-8。结构校验不能替代业务校验：日期真实性、IANA 时区、日期覆盖、起止顺序、重复 ID、场次总数、开放区间包含关系和过渡日限制均需前后端一致校验。

解析器要拒绝重复对象键，防止后面的 `id`/`schemaVersion` 静默覆盖前面的值。前后端错误应含稳定错误码、字段路径和中文说明，例如 `event.activities[0].sessions[1].end：结束时间必须晚于开始时间`。避免把原始秘密或 SQL 错误回显给用户。

严禁解引用上传文件中的任意远程 Schema/URL，不接受可执行脚本、HTML、文件路径或远程导入抓取。Markdown 如后续支持，必须安全渲染；第一版先用纯文本。

导入支持两种目标：创建新活动资料；有权限者更新明确选中的既有活动。更新前展示新增、修改、移除差异，提交带 `expectedRevision`。JSON 自带 `event.id` 不能绕过目标资源权限。

更新采用整包替换当前内容的原子提交，不在第一版引入含糊的“自动合并一半”策略。无变化重导入不得重复创建场次；可以报告“内容未变化”。任何一条非法则整包不写入。

导出必须产生能重新导入的同版本标准格式，不包含任何成员信息、令牌或服务端内部主键。普通个人数据备份使用**不同的 kind**，不能与活动包混用。

### 8.6 REDLAND 的实际使用资料

交付 `examples/redland-2026-template.json`：日期为用户给出的 `2026-10-02` 至 `2026-10-06`，每天一条；开放时间 09:00–21:00 只是此前待确认的默认值，必须在 `sourceNote` 和预览里明确标记；活动/场次列表先为空或仅使用经用户确认的数据。

不要伪造真实活动名称、官方场次、场馆规则或预约信息。仓库旧 catalog 的内容可提取成待确认资料，不自动宣称权威。真实资料缺失不能阻塞通用导入功能和空模板交付。

## 9. 模板更新与已确认安排

1. 管理员更新公共模板，只生成新模板版本。
2. 发起人选择“更新本队活动资料”后先看差异，再提交。
3. P0 采用清楚、保守的规则：改变日期、开放区间、时区、已有场次时间/删除场次或用于计算的默认设置时，递增小队 `scheduleRevision`，保留旧数据，并使受影响的已确认回复成为 `needs_review`。为减少复杂性，可在任何时间结构变更时要求全队复核。
4. 纯标题、说明的修订不改变时间语义；不要因此无意义地让所有人重填。
5. 已选场次保存稳定 ID 及选择时的时间/标题快照。场次被删除或改时间后显示差异，不能静默改约或凭空复活记录。
6. 在重新确认前，不把旧回复当成对新安排的承诺，不输出错误的“全员都有空”。
7. 时区在有成员确认后第一版不允许直接修改；引导复制为新小队或显式重新创建，避免暗中平移所有安排。

## 10. 免费架构与数据职责

默认实施：**GitHub + 现有 Vercel 前端 + Cloudflare Workers Free API + D1 Free 数据库**。

- 保留 Vite + React + TypeScript，不为这次上线迁到 Next.js/Vue 或重做所有 UI。
- Worker 使用 TypeScript 和小型路由层；D1 用参数化 SQL 与版本化迁移。可用轻量库，但避免引入不必要的 ORM/平台依赖。
- 共享的 TypeScript DTO、校验与时间纯函数放在 `shared/`，供前端和 Worker 使用，不能各写一份相互漂移。
- Zustand 负责 UI 与内存状态。IndexedDB 负责草稿、最近记录、离线快照、旧数据保护；很少量偏好可继续 localStorage。
- 已成功提交的在线小队数据以云端为共同数据源。草稿是本地数据，不等于在线提交。
- 不把数据库放在 Vercel 函数本地磁盘，不把私密数据提交 GitHub，不把 KV/内存对象当成唯一数据库。
- 不要求购买域名。使用部署时实际可用的免费入口，并核实 Vercel Hobby 非商业个人用途约束。

第一版数据库建议以“小队元数据＋成员独立回复”为核心，不必把每一分钟展开成一行：

| 逻辑实体 | 数据职责 |
| --- | --- |
| 公共模板及其版本 | 稳定 ID、发布状态、不可变的活动包、内容版本 |
| 小队 | 标题、状态、事件配置快照、scheduleRevision、来源模板版本 |
| 成员 | groupId、memberId、昵称、状态、个人回复版本 |
| 成员回复 | 本人可参与区间、场次选择与快照、手动忙碌、bufferMinutes、确认时的小队版本 |
| 访问凭据 | 哈希、作用域、资源归属、过期/撤销信息 |
| 必要的审计/幂等记录 | 脱敏操作类型、资源 ID、操作 ID、时间；不记录凭据和私密内容 |

可将每位成员的完整回复作为一个经严格校验的 JSON 文档原子更新，使用 `(group_id, member_id, revision)` 等索引/约束；不要每次修改一个成员就覆盖整个小队快照。模板/小队的内容快照也可用版本化 JSON，避免赶工时拆出大量没有必要的表。

### 10.1 并发与事务

- 更新使用 `expectedRevision`，在数据库层执行 compare-and-swap，而不是先读取再无条件覆盖。
- 影响多行的操作用 D1 当前实际支持的事务性批处理或等价原子机制；不要照搬并不适用的长事务/连接池代码。
- **CAS 更新影响 0 行不是 SQL 异常**。不能认为放进 batch 就会自动阻止后续写入；条件更新失败时，相关从属写入也必须被条件约束或整体拒绝。
- 提交同时校验当前 `scheduleRevision`。个人回复版本正确但活动版本已变，也应 409 并要求复核。
- 创建、加入、提交、导入都有操作 ID / 幂等设计。网络超时后安全重试不会重复产生小队、成员或场次。
- 相同 operationId 携带不同内容应拒绝；幂等记录的作用域必须绑定授权主体/目标。
- 删除、失效、关闭操作不能只改变前端列表。云端状态、权限与必要引用必须一致。

## 11. 免注册身份与隐私

### 11.1 作用域分离

至少区分：小队管理凭据、小队邀请凭据、成员个人编辑/恢复凭据、平台管理员凭据。

使用 CSPRNG 产生至少 256 bit 的随机能力凭据；资源 ID/昵称/短数字码不是认证。服务端仅保存可验证的凭据哈希或等价安全存储，不把全部原始 token 存入普通业务表。

推荐成员加入与创建请求在发出前由客户端生成并暂存自己的高熵凭据及 operationId，服务端只保存哈希并返回资源标识，以便“已写入但响应丢失”后安全恢复。若采用服务端签发，则必须解决首次响应丢失与安全恢复问题；不能靠猜名字找回，不能凭 operationId 向无认证者重放密钥。

### 11.2 邀请与恢复链接

- 群聊默认只分享邀请链接和二维码，不分享管理/个人编辑链接。
- 私密凭据放 URL fragment，读取后立即用 history.replaceState 清掉可见凭据；请求用 Authorization Bearer 或经过验证的等效方案，不把 token 放查询字符串。
- 不安装会抓完整 URL/表单内容的分析或会话回放脚本；日志必须脱敏。
- “恢复链接”本身等效于对应权限，页面提示妥善保存。个人凭据只允许编辑本人；管理凭据不能无声冒充成员。
- 能撤销/轮换邀请和相关凭据；被移除成员的原 token 不能继续读写。对撤销前已下载的离线副本，不能承诺远程抹除。
- 默认保留设备上的访问能力，但用户能明确退出/移除本机记录。清除本机与删除云端是不同按钮。
- 不采用依赖第三方 Cookie 才能工作的跨域登录方案。使用 Bearer 时说明 XSS 风险并落实 CSP、安全渲染与最小持久化；不要把 localStorage/IndexedDB 说成加密保险箱。

### 11.3 平台管理员的最小可用方案

不建完整用户中心。提供 `/admin`，可用部署时生成的高熵管理员入口凭据交换短期、可撤销管理会话；引导文档说明怎样安全初始化和轮换。根凭据只在 Worker Secret 中验证，不放入 `VITE_*`、代码、README、示例或提交记录。

后台会话尽量只驻留内存/sessionStorage，合理过期；退出能撤销。后台路由需要真正鉴权和失败限流，不能只用“隐藏地址”。

初次上线采用轻量、可配置的创建保护：例如 `CREATION_MODE=invite` 时，管理员向领头人提供站点创建码；普通成员只凭小队邀请加入，不需要这个创建码。若切换开放创建，必须有实测有效的免费防滥用措施。不要默认无限匿名建队，也不要因为没配置保护就自动放开生产。

### 11.4 共享内容最小化

- 普通小队成员和发起人的结果接口只得到必要名字、状态、可用/忙碌区间、版本与更新时间。
- 本人的安排标题、地点、备注只有本人可读；默认不向其他成员和发起人返回。
- 选择公共场次时，公共活动表本身可见，但“谁选了什么”不能因为服务端返回原始安排而被默认暴露。
- 不用 CSS 隐藏敏感字段；API DTO 必须裁剪，并做直接请求测试。
- 活动包导出绝不包含个人数据。个人备份默认不含权限凭据，私密恢复包如提供，必须是独立入口并明确风险。
- 云端默认并非端到端加密。隐私文档须诚实说明平台运维层的访问可能性，不能声称管理员在技术上绝对无法读取数据库。
- 页面提供个人删除/退出、发起人关闭与删除、公开模板下架等对应流程。删除不要伪装成只清本地。

### 11.5 请求与限额

所有写请求验证身份、资源归属、请求体大小、结构和业务规则；使用参数化 SQL。CORS 只允许实际前端 origin 与明确开发环境，不能允许任意 `*.vercel.app` 读取私密 API。

成员回复建议上限：31 天、每位成员 500 条忙碌/场次记录、每天最多 24 段可参与区间；小队先限定 50 名成员，额度由共享常量、API、UI 和文档一致表达。不要通过静默截断满足上限。

限流要适应多人共用同一会场 Wi-Fi：创建与无效认证按来源限流；成员合法写操作以凭据/成员为主要维度，辅以宽松来源保护。不能让一个用户提交后整个同 IP 小队都无法填写。

## 12. 同步、离线、PWA 与配额控制

1. 输入自动保存本地草稿；“提交”才发送在线确认。点击提交后网络失败，保留草稿，不能显示“已提交”。
2. 页面打开、主动刷新、本人提交成功后读取结果。可见且在线时默认最多每 60 秒自动刷新一次；隐藏页面停止，异常按 1/2/4/8/15 分钟退避。避免多组件重复轮询。
3. 先提供“待提交”与“重试提交”，不要为了后台自动提交上复杂离线同步框架。涉及活动版本变更必须重新校验，不能联网后覆盖新配置。
4. 结果显示服务端数据更新时间、最后成功获取时间和过期提示，不把页面当前时间标成数据更新时间。
5. Service Worker 缓存静态资源；私密 API 响应不进入公共 Cache Storage，不被 navigation fallback 当成 HTML。私密响应 `Cache-Control: private, no-store`；本地离线快照通过应用层按小队/成员隔离。
6. 首次未访问时不能声称完全离线可用。语言包和 OCR 资源缓存状态与基础网页缓存状态分开。
7. 更新 PWA 不得强制刷新丢草稿；提供合理的新版本提示，保持旧协议兼容窗口。
8. 免费额度用尽/Worker 不可用/超时/返回 HTML 错页时，保留本地数据并明确线上暂不可用；不自动付费升级，不反复无间隔重试。
9. D1 读写走有索引的小队范围查询；不要全表扫描、每分钟一行或为每个 UI 状态写数据库。可以在本人提交时生成安全的个人可用区间投影，与回复 revision 一起原子保存，避免每次读结果都重算全队原始安排；小队时间版本改变时，该投影必须失效并等待复核。
10. 云端备份与本机草稿不是一回事。明确哪些数据提交过、哪些只在此设备。
11. 上线前实测中国大陆实际使用网络的前端和 API 可达性；远程机器能访问不等于用户现场能访问。若没有真实设备/网络证据，列为待验，不能写“国内网络验证通过”。
12. 若实测需要调整免费访问入口，先评估同源 API 代理或替代免费静态入口，明确来源变化对本地缓存/凭据的影响；不能临近上线未经说明更换全部数据库和账号体系。

## 13. 旧版数据迁移与兼容

- 检测旧 localStorage 键 `coukong`，先完整保留原始数据并提供下载，再进行校验与迁移。失败时原数据仍可导出，不能覆盖为默认空值。
- `10-02` 等旧日期只在用户明确确认“旧 REDLAND 2026 数据”后补为 2026 日期；其他未知来源不能按当前年份猜测。
- 用户自己的旧预约可导入本地“旧版 REDLAND 安排”，然后由用户选择加入哪个在线小队并确认提交。禁止自动公开上传所有旧数据。
- 旧朋友只是静态快照，不能替他们创建“已确认”的真实在线成员，不能冒名提交。提供只读兼容视图/离线比对或导出保留入口，并明确其静态属性。
- 旧 `#d=...` 链接仍有解码、版本校验和安全预览入口，不被新路由吞掉。解压前限制输入长度，解压过程应隔离到有超时的 Worker 或等效可中止任务，并限制输出体积；不能只在无限解压完成后才检查大小。
- 旧备份、活动包、个人新备份分别识别，禁止混用错误入口导致覆盖。
- 改成 IndexedDB 后增加明确 hydration 状态；不能尚未读完就判定是新用户并写入默认数据。
- 本地恢复点能防误操作，但不能防用户清空网站数据；文档不能把它当成异地备份。

## 15. API 合同与错误处理

基础路径建议 `/api/v1`。以下资源语义为必需；路径若调整，必须同步 API 文档、前端、测试和帮助，不能留下两套混乱接口。

| 方法/资源 | 权限与行为 |
| --- | --- |
| `GET /health` | 不含秘密的进程存活、构建版本；不伪装为数据库就绪 |
| `GET /ready` | 轻量数据库/迁移就绪检查，不执行破坏性操作 |
| `POST /groups` | 校验创建保护；创建小队、发起人权限与可选本人成员；支持幂等 |
| `GET /groups/:groupId` | 本队邀请/成员/管理权限，返回安全小队信息 |
| `PATCH /groups/:groupId` | 发起人；expectedRevision；编辑状态/基本信息 |
| `POST /groups/:groupId/join` | 有效邀请；创建独立成员，安全幂等，不按名字认领已有成员 |
| `GET /groups/:groupId/members` | 本队读取；仅安全状态 DTO，不含任何编辑 token/私密备注 |
| `GET /groups/:groupId/members/:memberId/response` | 只允许该成员本人读取完整私人回复 |
| `PUT /groups/:groupId/members/:memberId/response` | 只允许本人；个人 revision 与 scheduleRevision 双检查 |
| `GET /groups/:groupId/availability` | 只返回安全可用区间、确认状态、版本、时间，不返回原始私密安排 |
| `DELETE /groups/:groupId/members/:memberId` | 本人离开/发起人移除；正确撤销相应权限，返回明确结果 |
| `POST /groups/:groupId/event-import/preview` | 发起人；服务端校验、差异与影响预览；无正式写入 |
| `POST /groups/:groupId/event-import/commit` | 发起人；版本检查、确认、原子导入；不能信任可篡改的预览结果 |
| `GET /groups/:groupId/event-export` | 本队允许读取者；标准活动包，无个人数据 |
| `POST /groups/:groupId/invite/rotate` | 发起人；旧邀请失效，既有成员权限按明确策略处理 |
| `DELETE /groups/:groupId` | 发起人；二次确认，级联/受控删除，不能误删公共模板 |
| `GET /templates` | 只列已发布公共模板，分页，不暴露私人小队 |
| `/admin/session` | 管理员会话建立/退出；强鉴权、限流、无秘密回显 |
| `/admin/templates` 相关资源 | 管理员创建/校验/发布/更新版本/下架模板 |

成功返回 `{data: ...}`。失败返回 `{error: {code, message, fields?}}`，使用准确的 4xx/5xx。建议稳定码包括：`INVALID_EVENT_PACKAGE`、`INVALID_TIME_RANGE`、`UNSUPPORTED_TIMEZONE_DATE`、`VERSION_CONFLICT`、`RECONFIRM_REQUIRED`、`INVALID_CAPABILITY`、`FORBIDDEN`、`GROUP_CLOSED`、`LIMIT_EXCEEDED`、`SERVICE_UNAVAILABLE`。

数据解析、请求超时、JSON 失败、数据库失败与权限失败都要有可见状态和重试出口。不能吞错并返回空数组，导致用户误以为大家都没安排。

## 16. 免费部署、备份与运营要求

### 16.1 环境分离与初始化

- 本地开发、预发布、生产使用不同 D1 数据或严格隔离资源；不能让预览部署随意写生产数据库。
- 前端公开配置只放 API 地址、公开站点配置等。Cloudflare API token、管理员根凭据、创建码哈希等只在安全的部署/Worker Secret 范围。
- `.env.example` 必须解释哪些值用户要准备、在哪填、哪些不能 `VITE_` 前缀。
- 使用版本化 SQL 迁移；已应用文件不可回改。迁移前备份，非破坏性优先。
- Vercel SPA 深链接刷新应工作；前端资源路径、manifest、图标、帮助、下载示例正确。
- 跨域访问明确处理 CORS 预检、Authorization 与缓存，不依赖浏览器安全限制被关闭。
- 不夸大“一键部署”：Vercel 按钮至多完成前端部分；D1、Worker、权限与环境变量需要的步骤必须说明。

### 16.2 构建和开发脚本

尽量沿用当前包管理器，提交 lockfile，固定实际测试过的 Node/包管理器版本，不为了“最新”做无关大版本升级。

根目录至少提供这些真实可运行脚本或清楚的同义命令，并在 README 对齐：

`dev`、`dev:all`、`build`、`typecheck`、`lint`、`test`、`test:integration`、`test:e2e`、`docs:check`、`verify`、本地/远程迁移命令、Worker 部署命令。

`verify` 聚合类型、lint、单元、集成、文档和构建；浏览器测试可独立但属于发布必跑项。所有命令要在实际环境运行，不得只写 package.json 却没有测试实现。

无云端凭据时，`dev:all` 必须仍能启动本地真实 Worker/D1 开发环境。生产构建不能自动把演示接口作为 API 兜底。

### 16.3 备份与恢复

上线前导出旧版部署/数据迁移依据；D1 上线前和重要活动资料更新前做受控备份。提供可执行的导出命令和隔离恢复步骤，用实际恢复验证，而不是仅检查文件生成。

私人数据库导出不提交 GitHub、不作为公开构建产物。个人/活动导出与数据库全量备份明确区分。平台免费恢复能力仅作补充，不代替验证过的导出方案。

P0 不自动删除尚在使用的小队。若没有实现自动保留期限和清理任务，文档必须如实写“手动删除/清理”，不能承诺 30 天自动删除。后续自动清理需显式规则、提前告知和独立测试。

### 16.4 免费额度的证据与限制

本提示词编写时官方资料显示 Workers Free 每日 100,000 请求、每次 10 ms CPU；D1 Free 每日 500 万行读、10 万行写、总存储 5 GB。它们是不同维度，不能互相代换。自 2026-09-01 起官方明确执行 D1 免费每日读写限额，超额查询失败，既有数据不因此删除。

执行时核实最新规则并在运维文档写核查日期与官方来源。不要主动升级账户。压力验证应覆盖预期使用规模，特别是批量 JSON 校验的 CPU、重复轮询和有索引查询；最大限制如果没有实测，标明未证实，不宣称可无限扩展。

### 16.5 真实上线而不是只交代码

顺序应为：本地完整闭环 → 隔离预发布部署 → 三个独立浏览器身份实际写入回读 → 备份恢复 → 手机与网络验收 → 生产部署 → 只读核验版本、路由、API 就绪和示例下载。

生产演练需要写数据时，只使用预先明确的测试小队并逐项记录、清理，不运行可能修改真实用户的批量测试。禁止为通过健康检查返回假的数据库成功。

没有授权/凭据或真实网络条件时，应交出精确的阻断清单和可继续的命令。不得说“已经上线”，不得留下无法识别的泛泛 TODO。

## 17. 实施阶段：每阶段都有独立验收

目录可适度调整，但不要在临近使用时全面重排已有工程。推荐保持现有 `src/`，新增 `worker/src/`、`worker/migrations/`、`shared/`、`schemas/`、`examples/`、`tests/` 和 `docs/`。

### 阶段 A：基线、合同、测试骨架

**涉及**：原仓库说明、依赖锁、`shared/types.ts`、`shared/event-validation.ts`、`schemas/`、`examples/`、`docs/implementation-plan.md`。

先记录原构建结果、当前版本和原功能，再把本需求拆成带勾选任务，不要只计划不执行。建立 DTO、JSON Schema、精确时间约定，落地最小例子与语义校验。

**验收**：原工程状态有记录；有效示例通过，重复 ID/越界/非法分钟/未知版本等失败；Schema 和共享校验一致。

### 阶段 B：分钟算法与状态机

**涉及**：`src/lib/availability.ts`、`shared/time.ts`、`shared/availability.ts`、对应单元测试。

先写第 5.4 节失败测试，再实现无舍入的合并、补集、交集、缓冲与状态门禁。旧可复用函数迁移/封装，不重复实现。

**验收**：精确样例全绿；未提交不会变全天可用；跨午夜缓冲和相邻边界正确；网格变化不改变结果。

### 阶段 C：真实多人后端与权限

**涉及**：`worker/src/index.ts`、路由、权限、仓储、SQL 迁移、`shared/api.ts`、API 集成测试。

先实现创建→加入→本人提交→另一身份读取安全结果；随后补 CAS、幂等、撤销、管理员最小入口、创建保护和模板版本。

**验收**：独立身份互相看到已提交变化；不能编辑别人、跨队访问、读取私密备注；并发仅一份成功；数据库重启/重新部署后已提交数据仍存在。

### 阶段 D：用户流程与分钟编辑界面

**涉及**：`src/App.tsx`、首页/小队页面、`src/ui/TimeAxis.tsx`、时间区间编辑器、草稿存储、样式。

先闭环简单约饭，再接场次。默认 15 分钟选择、5 分钟可切、手动 1 分钟。完成确认/草稿/错误/空/加载状态，深链接和手机操作。

**验收**：一名发起人和两名成员无需开发工具即可完成一次凑空；`13:07–13:52` 输入到导出不变；375px 页面可操作，无整个页面横向溢出。

### 阶段 E：JSON 导入、模板管理、变更复核

**涉及**：导入预览页面、后台模板页、服务端导入路由、版本模型、帮助下载。

实现同一校验器、可读错误、无变化重导入、原子更新、版本冲突、公共模板与私人小队隔离。

**验收**：一包非法内容不产生部分数据；两个小队引用同一模板且互不读写；更改已选择的场次导致复核而不是静默改约；导出回导一致。

### 阶段 F：旧数据、离线和 PWA

**涉及**：`src/store.ts`、旧 codec、IndexedDB 数据层、PWA 配置、OCR 入口。

处理旧数据保护、异步加载状态、旧分享预览、静态朋友快照、本地草稿、离线快照、PWA 更新保护与原有 OCR 的兼容边界。

**验收**：旧数据未丢；旧链接可预览；离线不假称已提交；重连不覆盖新配置；他人的静态分享不变成其真实在线确认。

**涉及**：第 14 节全部文档与示例、CI、环境示例、部署配置、验收记录。

**验收**：所有 P0 通过；未完成的 P1 隐藏或明确为未交付；线上 API/数据/版本真实；恢复步骤可用；用户能按新手文档完成操作。

## 18. 发布测试矩阵：不能只写“已测试”

测试命名可调整，但每项断言必须落地。纯函数用单元测试，权限和并发用真实本地 D1/API 集成，用户流程用独立浏览器上下文，外部环境保留真实证据。

### 18.1 时间与状态

- `minute_precision_survives_roundtrip`：`09:05`、`13:07–13:52` 保存/刷新/导出回导完全不变。
- `display_step_does_not_change_data`：5/10/15/30 切换不修改已存数据与共同空闲。
- `exact_intersection_with_per_member_buffers`：第 5.4 节三段结果和过滤结果严格一致。
- `half_open_boundaries`：首尾相接无冲突，零长/倒序区间拒绝。
- `multiple_open_and_presence_intervals`：午休与中途离开不会被算为可用。
- `midnight_buffer_spills_to_adjacent_day`：前日 23:55 结束、10 分钟缓冲能遮挡次日 00:00–00:05。
- `twenty_four_only_allowed_as_end`：结束 24:00 合法，开始 24:00 非法，23:30–00:30 要拆分。
- `timezone_does_not_follow_device`：设备时区变化不改变上海活动日期和起止。
- `unsupported_dst_date_is_rejected`：若未完整支持 DST，明确拒绝相应过渡日，不能算错后通过。
- `unsubmitted_not_free`：刚加入、空草稿、全部无人确认都不出现全员可用。
- `confirmed_empty_means_unavailable`：明确确认不能参加有效，不等于未填写。
- `selected_subset_is_exact`：未选者不影响，选中未确认者不能被自动忽略。
- `schedule_change_requires_reconfirmation`：旧回复保留但不算作对新时间配置的确认。

### 18.2 JSON

- 最小包、完整示例、REDLAND 空模板通过 Schema 和业务校验。
- 非法日历日期、未知时区/版本、重复对象键、重复日期/活动/场次 ID、缺日期、越界场次、空白标题、错误类型和多余字段明确失败。
- 多活动并行场次合法；每日开放区间重叠非法。
- 超大小/超数量拒绝且数据库不变。
- 非法包不部分导入；同包重复导入无重复记录。
- 更新预览与提交之间版本变化返回 409。
- 伪造 `event.id`、成员字段、管理员字段不能绕过权限。
- 导出无个人信息/凭据且可无损回导。
- 站内下载示例与仓库文件内容一致。

### 18.3 权限、同步与安全

- 两人同名不覆盖，改名不改变身份。
- A 不能读写 B 的完整私人回复；发起人也不能冒充 B。
- 小队一的凭据不能访问小队二；已撤销/被移除/伪造 token 失败。
- 公共结果中没有私密备注、安排标题、编辑凭据。
- 两个设备对同 revision 修改仅一个成功，另一份草稿保留。
- 活动 revision 变动与个人提交竞态得到正确冲突。
- 创建/加入/提交响应丢失后重试不重复记录；operationId 不可当作取回凭据的通行证。
- 断网、超时、配额失败、API 返回非 JSON 时不显示保存成功，不清空已有数据。
- 管理员 Secret/私密环境变量不进入前端 bundle、日志、示例与 Git。
- SQL 注入和 HTML/XSS 文本作为普通内容处理，不能执行。
- 共同 Wi-Fi 多个合法成员能正常填写，限流不误封全队。

### 18.4 兼容与浏览器

- 旧 localStorage 迁移成功与失败均保留原始内容；旧朋友不自动冒名加入。
- 旧 `#d=...` 正常码可预览，恶意/过大/版本不支持的码被安全拒绝。
- 首屏 hydration 不会把已有数据覆盖成新用户默认值。
- 375/390/430px 视口、桌面、键盘、深色、减少动态效果可用。
- 独立浏览器上下文分别扮演发起人/A/B，完成建队、导入、填写、修改和比对。
- 刷新深链接不 404；恢复链接权限正确；PWA 冷启动、更新、离线草稿不丢。
- 隐藏页面停止轮询；切回不会产生多个定时器。
- Playwright WebKit 只能算自动化浏览器证据，不能冒称 iPhone 真机或微信实测。

### 18.5 上线场景

**场景一：约饭。** 没有任何展位/IP/场次，发起人只填标题和日期，三个人填写不同分钟区间，得到正确交集。

**场景二：REDLAND。** 管理员导入五天活动框架，经用户补齐/确认真实场次与开放时间，两支小队共用模板，独立填写。重点检查 2026-10-03 的分钟级安排、个人缓冲和共同空闲。

**场景三：资料更新。** 先有人选场次，再修改该场次时间；系统展示差异、保留旧安排、要求复核，不默默改变确认状态。

**场景四：故障恢复。** 离线编辑后重连、两个设备冲突、错误 JSON、旧备份恢复、预发布数据库导出到隔离环境恢复，均有明确结果。

## 19. 最终交付与完成定义

交付必须包含：

1. coukong 功能分支/PR/提交标识，必要源码、锁文件、迁移、配置示例、测试、CI；无真实秘密。
2. 可构建前端与可部署 Worker，不是空 API 壳；受控的版本/提交信息。
3. 完整文档中心、站内帮助、Schema、三个可导入样例和错误样例。
4. 新用户能照着完成的指南；管理员能照着上传真实活动 JSON 并发布；部署者能照着完成免费部署。
5. 实际运行的命令、结果、测试环境、自动化/人工证据和未运行项。
6. 若已部署：真实前端 URL、API 就绪结果、部署对应 commit、生产配置检查结果；私密管理/恢复入口通过安全方式交付，不能放公开 README/issue。
7. 如未部署：精确到权限/资源/变量/步骤的外部阻断清单，不含凭据明文；本地已完成部分与用户必须操作的最短步骤分开。
8. 旧数据保护、云端备份与回滚步骤，以及真实数据缺失项，特别是 REDLAND 未确认的开放时间/官方场次。

只有“真实多人数据闭环＋分钟级结果正确＋权限隔离＋完整用户/JSON/部署文档＋可验证部署”同时成立，才能把相应范围标为上线完成。P1 可以明确延后，但不能把 P0 缺项藏在“未来计划”。
